## Risks requiring engineering/security review
1. HCW stores `User.password` in its Prisma model; source must prove strong password hashing, never plaintext persistence, reset-token expiry, and breach-safe logs.
2. HCW payment config includes Stripe secret-key fields in the schema. Secrets must be externalized and encrypted; schema presence alone is a risk signal.
3. TPT’s broad compliance labels and RLS comment are claims/configuration cues, not independent assurance. Verify migrations, SQL policies, query scoping, access tests, and export/delete behavior.
4. Both systems require a PHI logging review: request bodies, error traces, media events, messages, and generated documents must not leak sensitive content.
5. None of the checked-out references proves Bangladesh phone identity, WhatsApp consent, retention, backup restore, or clinician-level approval for AI output.

Medigo-specific risk: the clients directly mutate Firestore and use a hard-coded Agora App ID. Firebase Security Rules, project ownership, exposed config, Firestore indexes, Storage Rules, and least-privilege access must be reviewed before treating the app as suitable for PHI.

OpenEMR’s security surface is more mature and explicit than the original inventory recorded: OAuth/API authorization documentation and tests, GACL classes, `audit_master`/`audit_details`, `src/Common/Logging/Audit/`, query auditing, and audit reporting are present. GPL code and operational complexity do not substitute for an independent threat model; review SQL scoping, portal/API authorization, OAuth client handling, document access, and secret configuration before using it as a pattern.

This is a technical comparison, not legal, compliance, or security certification advice.
